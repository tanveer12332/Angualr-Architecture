# 🧩 Micro-Frontends (MFE) Architecture: Masterclass Notes

## 1. Module Federation (Webpack 5 & Native Federation)
- **Core Concept:** Decompose large monolithic frontends into a **Host (Shell)** and independently deployable **Remotes**.
- **Native Federation:** Modern Angular (v17+) uses Native Federation with esbuild/Vite and standard browser Import Maps instead of legacy Webpack dependencies.

## 2. Dependency & Version Governance
To prevent downloading duplicate framework bundles and runtime injector conflicts:
- `singleton: true`: Ensures only one instance of `@angular/core` or `rxjs` runs in the browser.
- `strictVersion: true`: Enforces version compatibility across Host and Remotes.
- `requiredVersion: 'auto'`: Aligns shared dependency constraints with `package.json`.

## 3. Cross-MFE Communication (Loose Coupling)
Avoid sharing heavy global Redux/NgRx stores across MFEs. Prefer loosely coupled patterns:
1. **URL / Route Parameters:** Primary mechanism for passing context during navigation.
2. **Browser CustomEvents:** Framework-agnostic pub/sub via `window.dispatchEvent`.
3. **Minimal Shared Libraries:** Lightweight singleton RxJS services strictly for Auth tokens or global user context.

## 4. Architectural Trade-off
- Use **MFE** when multiple autonomous teams need independent CI/CD pipelines.
- Use an **Nx Modular Monolith** for small-to-medium teams to avoid operational overhead.
