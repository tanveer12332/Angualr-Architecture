# 🏢 Enterprise Project Structure & Monorepos: Masterclass

## 1. Nx Monorepo Architecture
- **Why Monorepo?** Centralized management of multiple apps (ERP, Admin, Customer Dashboard) sharing core logic.
- **Key Features:**
  - `nx affected`: Runs CI/CD tasks only on modified codebases, saving hours of build time.
  - **Computation Caching:** Local/remote caching prevents redundant builds.
  - **Dependency Graph (`nx graph`):** Interactive visual mapping of project interdependencies.

## 2. Domain-Driven Design (DDD) in Frontend
Organize code into vertical business domains and strict horizontal library layers:
- **Domains (Vertical Slices):** e.g., `inventory`, `billing`, `users`.
- **Layer Types (Horizontal Slices):**
  - `feature`: Smart container components, state orchestration, routable views.
  - `ui`: Dumb, stateless, reusable presentational components.
  - `data-access`: API services, state management (NgRx/Signals), models.
  - `util`: Pure helper functions and formatting utilities.

## 3. Module Boundary Rules & Governance
- **The Problem:** Developers importing internal files across domains, creating tight coupling and spaghetti architecture.
- **The Nx Solution:** `@nx/enforce-module-boundaries` ESLint plugin.
- **Implementation:** Using project tags (`scope:inventory`, `type:ui`) to enforce strict import restrictions at build/lint time.
