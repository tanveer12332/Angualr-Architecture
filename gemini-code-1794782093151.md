## 1. Standalone Components vs. NgModules

### 🔴 The Legacy Approach (NgModules)
In legacy Angular (v2 through v15), every component, directive, and pipe had to be declared inside an `NgModule`.
* **Boilerplate Overhead:** Every new feature required creating and maintaining module files.
* **Global Scope & Duplicate Imports:** Shared directives/pipes had to be imported across multiple modules repeatedly.
* **Poor Tree-Shaking:** Tightly coupled modules made it harder for bundlers to strip out dead or unused code, leading to larger initial bundle sizes.

### 🟢 The Modern Architecture (Standalone Components - Default in v16+)
* **Direct Dependencies:** Standalone components (`@Component({ standalone: true, imports: [CommonModule, MatButtonModule] })`) explicitly declare what they need right inside the component decorator.
* **Simplified Lazy Loading:** Routing no longer relies on complex `loadChildren` module syntax. You can lazy-load components directly:
